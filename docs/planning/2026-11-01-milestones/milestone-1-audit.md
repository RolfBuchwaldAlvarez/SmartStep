## What the classifications mean

- **Code-supported:** a concrete implementation is present, but not an observed runtime acceptance pass.
- **Partial/gap:** some implementation exists, with an identifiable mismatch, incomplete wiring or missing acceptance evidence.
- **Absent:** no implementation found after whole-tree inventory/search, not simply because a single file lacks a symbol.
- **Decision-dependent:** the PDF is ambiguous or platform behavior needs approval before a definitive acceptance assertion.

No requirement is called runtime-passed by this audit. No Android app tests, build or device interactions were run.

## Later-feature inventory

At this SHA, application feature directories are `home` and `myprofile`; Route has MyProfile/Home; Room database is profile-only; manifest has no tracking service or notification/foreground-service declarations. Whole app-source inventory and searches for Sensor/Service/Notification/Report/Coach found permission-prompt UI uses, but no actual sensor listener, daily ledger, tracking service, activity metrics, AI adapter/chat or report feature. M2–M4 drafts therefore add those features rather than assuming hidden implementations. Recheck against the implementation base when each issue is promoted; do not use this dated inventory as a permanent assertion about current main.
